Values to many digits

Ask for f(x) at a rational x and you get two answers. The first is a double-precision float, computed at once. The second is a rational interval that provably contains the true value, narrowed until it is good to the number of significant digits you asked for. This page is about the second one: how a finite computation can promise something about e^(1/3), which no finite decimal equals.

Reading the answer

Results are shown in RatMath's interval notation. 0.46235716975[69:70] means the value lies between 0.4623571697569 and 0.4623571697570: the digits outside the brackets are shared by both ends, and the bracket gives the last digits of each end. When the two ends are equal the value is exact, and only one number is shown.

"Digits" means significant digits relative to max(1, |value|). So 20 digits of e^30 ≈ 1.07·10¹³ is an interval about 10⁻⁷ wide, while 20 digits of sin(10⁻⁵) is an interval about 10⁻²⁰ wide. Values near 0 are measured against 1, because "20 significant digits of a number that might be 0" has no finite answer.

import { fn } from "@ratmath/analytic";

const v = fn("exp(x)").value("1/3", { digits: 50 });
v.quick.value;     // 1.3956124250860895 (a double, right away)
v.exact();         // RationalInterval, width ≤ 10^-50 · 1.39…
v.exactStage().via // "certified enclosure at 191 bits"

fn("x^2 + 1/x").value("3/7").exact();   // 370/147 exactly: no irrational step

Series with a tail you can bound

Every elementary function is computed at a point by summing a power series and adding an explicit bound for the part that was not summed. A series alone is not enough: e^x = Σ xᵏ/k! converges for every x, but at x = 100 its largest term is about 10⁴², so the sum would need hundreds of digits of cancellation. The trick in each case is to move the argument to where the series converges fast, sum there, and move back with an operation whose effect on the error is known.

Precision bookkeeping

Each step that can lose accuracy is paid for in advance with extra bits. Squaring doubles a relative error, so s squarings in the exp reduction cost s bits; the series is summed with that many more. Terms are rounded to dyadic rationals (a whole number over a power of 2) so their denominators stay small, and every rounding adds one unit in the last place to a running error term that becomes part of the interval. Nothing is estimated: the width of the answer is an upper bound built from the tail bound, the rounding count and the reduction error.

If the first precision is not enough (a value close to a large cancellation, or a composite like exp(sin(x)) whose inner error grows through the outer function), the certified stage doubles the working bits and tries again, up to maxBits (default 8192). Each try is a progress tick with a partial interval, so a page can show the answer sharpening.

Composite formulas

A formula like exp(sin(x))·x is evaluated as a Taylor model of order 0 on the point domain {x}: each function receives an interval and returns an interval. At a point that is ordinary interval arithmetic with the certified point values above. The answer is good to the digits asked for when the final width says so, not because each step was given a fixed number of digits.

import { enclose, constants } from "@ratmath/analytic";
import { R } from "@ratmath/core";

enclose.exp(R`1/3`, 200);   // an Iv with relative width about 2^-200
constants.pi(256);          // π to 256 bits
constants.e(128);
