@ratmath/analytic

Answers about functions that come with a proof

A JavaScript library for calculus on exact rational numbers. Ask for a value, a range, an integral, the zeros or the solution of a differential equation. You get a floating-point answer at once, then an interval that is guaranteed to contain the true answer.

Move the slider. The curve and the guesses follow at float speed. When you stop, the zeros are proven, each one in its own small bracket that is shown to contain exactly one. The integral and the range come back as intervals, and the true values are inside them.

Why intervals

Most values of exp, sin or an integral are irrational, so no fraction is exactly right. RatMath's answer is a rational interval that certainly contains the true value, as narrow as you ask. Every step that could lose accuracy (a truncated series, a rounded constant, a range over a whole interval) is counted and added to the interval. So the result is a statement you can rely on, not an estimate.

Underneath sits the Taylor model: an exact polynomial plus an interval remainder, valid on a whole interval of inputs. Arithmetic, composition, integration and ODE steps all act on these models and keep that guarantee.

A first program

import { R } from "@ratmath/core";
import { fn, zeros, ode } from "@ratmath/analytic";

const f = fn("exp(sin(x))*x");
f.value("1/3").quick.value;          // 0.46235716975704894 (float, at once)
f.value("1/3", { digits: 30 }).exact();  // RationalInterval, 30 correct digits
f.integral(0, 1).exact();            // certified ∫₀¹
f.derivative().toString();           // "exp(sin(x))*cos(x)*x + exp(sin(x))"

zeros("x^3 - 3x + 1", [-3, 3]).exact();   // three brackets, each with exactly one zero
ode.solve({ f: "y^2 + t", y0: "1/2", until: "1/2" }).exact().final;  // y(1/2), certified

Reference

Everything in the library

Numbers can be JS integers, bigints, strings such as "3/4" or "0.1" (decimals are exact), Core Rationals, or Core intervals such as R`1/2:1`. Functions marked R return a Refinement: .quick is the float preview, .exact() or await .settle() gives the certified answer. When a hypothesis fails (a log of something that can reach 0, a divisor that can be 0, a point outside the domain), the library throws an AnalyticError with a code and a reason. It does not return a bound it cannot prove.

Ask anything about a function

Type a formula, or a piecewise function such as x - n if n:x:!n+1. Names other than x become sliders in steps of 1/8. Choose which questions to ask. Each answer shows its float preview at once and its certified form when it arrives. Your last function is remembered in this browser.

Idea

Fast, then certified

Certified answers cost more than floating-point ones, sometimes a thousand times more. Someone dragging a slider needs a picture now; someone writing down a result needs it to be true. So every question returns a Refinement that can answer both ways. It is the same class the RatMath linear algebra and graphics libraries use, so one loop can drive all three.

const job = fn("exp(sin(3x))*x").range(R`0:3`, { digits: 6 });
job.quick;            // { stage: "float", value: [lo, hi], trust: "rough" }
for (const s of job.stages()) …   // float, then progress ticks, then the certified stage
job.exact();          // run to the end now (fine in a Worker)
await job.settle({ signal, sliceMs: 8, onProgress });   // the same, in time slices

How far to trust a preview

trust is good when the float computation is normally accurate (a value, an integral by Gauss–Legendre), rough when it can miss things (a range from samples can miss a narrow peak; zero guesses come from sign changes, so a double root is invisible), and unsure when the float answer is not finite.

Progress and partial answers

Progress ticks look like { stage: "progress", done, of, step, partial }. partial is the answer so far: a range that is already valid but still wide, an integral over the pieces done, the ODE steps validated so far, the zeros found so far. A display can sharpen as they arrive.

Sliders: live

const f = fn("a*sin(x)", { params: { a: 1 } });
const update = live((a) => f.with({ a }).value("1/2"), (stage) => show(stage.value, stage.exact), { idleMs: 30 });
slider.oninput = () => update(`${slider.value}/8`);

Each update shows the preview at once. Certified work starts once the input has been still for idleMs, runs in slices, and is cancelled by the next update, so only the latest question is ever finished.

Idea

Taylor models

A Taylor model on a domain D = [a, b] with centre c is a pair (P, I): a polynomial P with exact rational coefficients and a rational interval I, such that

f(x) − P(x − c) ∈ I for every x in D.

This is the basic object of validated numerics (Berz and Makino; Moore's interval analysis). It is stronger than a value: it describes f on the whole domain, so ranges, integrals and compositions come from it with the error already counted.

Arithmetic

Sums add polynomials and remainders. A product multiplies the polynomials exactly, keeps degrees up to the order, and bounds the rest: the dropped high-degree part over D, plus P·J + Q·I + I·J. Each bound is a range of an exact polynomial, so nothing is lost but what is deliberately moved into the remainder.

Elementary functions

For exp, sin, log and the others, the library composes the function's own Taylor series about g(c) with the model g. The Lagrange remainder f⁽ⁿ⁺¹⁾(ξ)/(n+1)!·hⁿ⁺¹ is bounded over the whole range of the argument: e^max for exp, 1 for sin and cos, and for log, 1/x and sqrt the argument's range must stay away from 0, or the library refuses. Coefficients that are irrational, like e^c, are certified intervals; their midpoints go into P and their radii into I.

const D = Domain(R`0:1/2`);
const x = TM.x(D, { order: 12 });
const g = exp(sin(x)).multiply(x);
g.coefficients;   // exact Rationals, in powers of (x − 1/4)
g.remainder;      // a tiny interval
g.range();        // Bernstein bounds with bisection
g.integral();     // certified ∫ over D

Derivatives

The remainder of a model says nothing about the derivative's error: f could wiggle inside I. So model.derivative() only works for exact polynomials, and derivatives are taken from the formula instead (symbolic d/dx), then modelled afresh with their own remainder.

Topic

Values to many digits

At a single rational point, the library sums each function's series with an explicit bound on the tail, after reducing the argument to where the series converges fast:

  • exp: halve the argument until it is below 1/4, sum Σ rᵏ/k! (the tail after k terms is at most twice the next term), then square back.
  • log: 2·atanh((q − 1)/(q + 1)) after scaling by powers of 2, with log 2 from the same series.
  • sin, cos: reduce modulo 2π with a certified π, then the alternating series; the uncertainty in π becomes a little more width.
  • atan, π: an alternating series for small arguments, argument halving otherwise; π from Machin's formula.
  • sqrt: an integer square root on scaled numerator and denominator, exact when the square is perfect.

The display uses RatMath's interval notation: 0.46235716975[69:70] means the value lies between 0.4623571697569 and 0.4623571697570.

Topic

Formulas and derivatives

fn(text) parses calculator notation into a plain tree of num, var, const, op and call nodes. The same tree can then be evaluated three ways: with floats for previews, as a Taylor model for certified answers, or with plain intervals for quick exclusion tests.

Symbolic d/dx

Derivatives follow the rules you know (sum, product, quotient, chain; d/dx aᵇ in general form), and simplify as they build: constants fold, 0·u and 1·u disappear, (uᵐ)ⁿ becomes uᵐⁿ. Because the derivative is a formula, its model has its own proven remainder.

fn("x^3 + 2x - 1/x").derivative().toString();   // "3*x^2 + 2 + 1/x^2"
differentiate(parse("atan(x^2)"), "x");         // an AST: 2*x/(1 + x^4)

Parameters and intervals

Names other than the variable are parameters: fn("a*x^2", { params: { a: "3/8" } }). A parameter may be an interval, { a: R`1:2` }; then every answer holds for every a in that range.

Non-smooth pieces

abs, min and max are modelled where they are smooth on the domain (the argument keeps one sign, or one argument stays on top) and refused where they are not. Split the domain there, or write the function piecewise.

Topic

Ranges and integrals

Bounding a polynomial

Evaluating a polynomial with interval arithmetic gives a valid range, but a loose one: x − x over [0, 1] comes out as [−1, 1]. The Bernstein form is better. Rewritten in the Bernstein basis on [a, b], the polynomial's range lies between its smallest and largest Bernstein coefficients, and the end coefficients are exact values. Splitting the interval tightens the bound quadratically.

Adaptive pieces

f.range(I) keeps a list of pieces, each with a Taylor model. The outer bound is the hull of the pieces' bounds. The inner bound comes from certified values at piece midpoints: the true maximum is at least the largest of them. Only the pieces that hold the current extremes are split, until outer and inner bounds agree to the requested digits.

Integrals

The integral of a Taylor model is the exact integral of P plus I·(b − a). f.integral(a, b) splits [a, b] until each piece's width meets its share of the budget, so effort goes where the function is hard.

Topic

Zeros, poles and extrema

Finding where f = 0 numerically is easy. Proving it is harder: that there is a zero in a bracket, that there is only one, and that there are none elsewhere. The library uses two engines.

Rational functions: exact

When f is built from + − × ÷ and integer powers with rational numbers, it is read exactly as N/D. Then:

  • Holes. G = gcd(N, D) cancels. Points where G = 0 are holes: f is undefined there, but the limit exists, and the library reports it.
  • Multiplicity. Yun's square-free decomposition writes N/G = a₁·a₂²·a₃³⋯ with each aᵢ free of repeated roots, so every root comes with its multiplicity, and every pole with its order.
  • Isolation. A Sturm sequence counts the distinct roots in any interval exactly. Bisection splits at the simplest rational in the middle half of each bracket, so roots like 1 or −2/3 are hit exactly, and irrational roots end in brackets like [1393/985, 1970/1393] around √2.

Everything else: Krawczyk

For a bracket X with midpoint m, Y ≈ 1/f′(m), and an interval bound F′(X) on the derivative,

K = m − Y·f(m) + (1 − Y·F′(X))·(X − m)

contains every zero of f in X. If K misses X, there is no zero. If K lies inside X, there is exactly one, and replacing X by K ∩ X narrows it quadratically, like Newton's method but with proof. Where F′(X) contains 0 (a double root, two close roots), the test cannot decide, so the bracket is reported as possible, with atMost: m when the m-th derivative is proven nonzero there: by Rolle's theorem, f then has at most m zeros there, counted with multiplicity.

At an exact zero, the derivatives that are exactly 0 there give a lower bound on the multiplicity. When Rolle's bound matches it nearby, the multiplicity is proven. So sin(x)² has a zero of multiplicity exactly 2 at 0, while near π it can only say "at most 2": no finite computation can tell a double root from two very close roots, or from a near miss.

Functions flat to every order

e^(−1/x²) and all its derivatives tend to 0 at x = 0. Near 0 it is smaller than any number the library can represent, so it cannot be told apart from 0 there. Those brackets come back as possible with bound, the proven maximum of |f| on them, and with no atMost, because every derivative is just as flat. Outside them f is proven positive.

Poles, extrema, inflections

Poles are zeros of denominators (and of cos inside tan) where the numerator is proven nonzero, and only where the blow-up reaches f. A division inside exp is not a pole of f: e^(−1/x²) tends to 0. Extrema are zeros of f′, classified by the sign of f″ or by the sign change of f′. Inflection points are zeros of f″ where f″ changes sign.

Piecewise functions

A piecewise function is a list of pairs: a region and a rule. The first region that contains x decides the rule. Regions use a betweenness chain on x:

regionmeaning
2:x:82 ≤ x ≤ 8
_:x:8    2:x:_x ≤ 8    x ≥ 2 (_ is an unbounded side)
2:!x:8    2:x:!82 < x ≤ 8    2 ≤ x < 8 (:! is a strict link)
2n :x:! 2n+12n ≤ x < 2n+1 for some integer n
_:x:!-1 || 1:!x:_a union: x < −1 or x > 1
all, else, otherwiseevery x

A name in a bound that is not a parameter is an integer variable. Bounds must be affine in it (like 2n + 1 or 3 − n/2). For each x the library solves for the integer n that fits, and the rule can use n too: x - n if n:x:!n+1 is the sawtooth. A region can also be a plain function x => boolean; it answers point questions, but ranges, integrals and zeros need breakpoints, which only chains provide.

fn("x^2 if _:x:1; 3 - x if 1:!x:2; 1/2 otherwise");
piecewise([["2n:x:!2n+1", "1"], ["2n+1:x:!2n+2", "-1"]]);   // a square wave
where`${a}:!x:${b}`;                                          // a Region from a template

Breaks

breaks([a, b]) lists each breakpoint with the value there (if any piece contains it), the limits from the left and right rules, and a kind. continuous means all three are proven equal. jump means the two limits are proven different. removable means the limits agree but the value is missing or different. That is what a plot needs to draw filled and open dots.

Questions piece by piece

Values, ranges, integrals, zeros, extrema and inflections are answered on each open piece with that piece's rule, then combined. A sign change across a jump is not a zero. The zero finder only looks inside pieces and at points where the value is exactly 0.

Topic

Differential equations

For y′ = F(t, y) with y(t₀) given, a step over [t₀, t₀ + h] works like this:

  1. Iterate Picard's map on polynomials to get P ≈ y on the step.
  2. Look for an interval I with Φ(P + I) ⊂ P + I, where Φ(y)(t) = y₀ + ∫ F(s, y(s)) ds is evaluated in Taylor-model arithmetic. Φ then maps the set of functions within I of P into itself. By Schauder's fixed-point theorem, and uniqueness for these smooth right-hand sides, the solution stays within I of P on the whole step.
  3. Shrink I by applying Φ again, or halve h and retry if no such I exists.

Steps chain through the enclosure at the end of each step. Step sizes adapt: h halves when validation fails, or while halving still shrinks the width a step adds, and doubles after a success. A solution that blows up ends with complete: false and a reason, never with a wrong enclosure.

ode.solve({ f: ["v", "-x"], vars: ["x", "v"], y0: [1, 0], until: 3 });   // a system
ode.solve({ f: "y", y0: R`1:101/100`, until: 1 });                        // an uncertain start

The wrapping effect

Systems are enclosed component by component, as boxes. A rotating flow turns each box, and the box around the turned box is larger. Over long spans the enclosure grows for that reason alone. Shorter spans, higher order, or (not built yet) preconditioned steps keep it tight.

Topic

Your own series

For a function given by its power series coefficients aₖ, the remainder after degree p needs an argument. series makes you name one and checks what it can:

  • alternating: the terms alternate in sign and shrink, so the tail lies between 0 and the first omitted term. Checked on the next 32 terms for every x in the domain.
  • ratio: |aₖ₊₁|·r ≤ q·|aₖ| with q < 1 beyond p, so the tail is at most the first omitted term divided by 1 − q. Checked on the next 32 terms.
  • lagrange: you supply M ≥ max |f⁽ᵖ⁺¹⁾| on the domain.
  • explicit: you supply the error.

What the library cannot check (the terms beyond the lookahead, your M, your error) is your claim, so the model is marked assumed, and describe() says so.
