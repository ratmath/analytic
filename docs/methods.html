First-order equations: the methods

The validated solver answers "what is y(2)?" with a proof and no formula. A course asks for the formula and for the method that finds it. firstOrder recognises the standard types of equation y′=f(x,y)y' = f(x, y)y′=f(x,y), carries out the method, and reports every step. exactEquation does the same for M dx+N dy=0M\,dx + N\,dy = 0Mdx+Ndy=0.

const s = firstOrder("x - 2*y");          // y' = x - 2y
s.type;       // "linear"
s.general;    // "y = 1/2*x - 1/4 + C*exp(-2*x)"
s.steps;      // [{ what, formula }, …]

const p = s.through(0, 1);                // the solution with y(0) = 1
p.solution;   // "1/2*x - 1/4 + 5/4*exp(-2*x)"
p.check(1);   // { agree: true, numeric: […], formula: […] }

A formula that has been checked

Every closed form here can be compared with the validated numerical solution. check(x1) solves the initial value problem to x1x_1x1​ with proven error bounds and evaluates the formula there with proven error bounds; the two enclosures of y(x1)y(x_1)y(x1​) must meet. For a solution given only as a relation G(x,y)=CG(x, y) = CG(x,y)=C, the relation is evaluated on the numerical enclosure and must contain the constant. A wrong formula fails this test, so a mistake in the algebra cannot pass unnoticed. A check takes from a fraction of a second to some seconds, depending on the equation.

An equation can be of several types: y′=xyy' = xyy′=xy is linear and separable. types lists all that apply and type is the one used; pass { method } to choose. A linear equation is solved as linear because that gives yyy outright. A separable equation gives a relation between xxx and yyy, reported as implicit, and where the relation is easily solved (a logarithm, a reciprocal, an arctangent) also as general.

The integrals

The methods need antiderivatives. antiderivative(tree, name) covers polynomials, rational functions by partial fractions, exponentials and sines of linear arguments with polynomial factors, and one level of substitution; it returns nothing unless differentiating its answer gives the integrand back. When an integral is not found, type is null and the validated solver is still there. The fuller engine is in the symbolic package.
