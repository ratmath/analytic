ε, N and δ, with certificates

The definitions of a limit and of continuity ask for a number: an NNN for each ε\varepsilonε, or a δ\deltaδ for each ε\varepsilonε. nFor and deltaFor find one, say why it works for every later term or every nearby point, and hand back a certificate that verifyCertificate rechecks by a different route.

const a = sequence("(2n + 1)/(n + 3)");
const r = a.nFor("1/100");
r.N;        // 498, and r.least is true: 497 does not work
r.reason;   // "the terms rise to the limit for n ≥ 1, so |a(n) − L| never grows from there; …"
verifyCertificate(r.certificate).valid;   // true

const d = deltaFor("x^2", 2, "1/100");
d.delta;    // 249/100000, a δ that works
d.largest;  // [0.00249843…]: the largest one, √4.01 − 2
deltaFor("x^2", 2, "1/100", { delta: "0.003" }).holds;   // false

An N for ε

an→La_n \to Lan​→L means: for every ε>0\varepsilon > 0ε>0 there is an NNN with ∣an−L∣<ε|a_n - L| < \varepsilon∣an​−L∣<ε for all n≥Nn \ge Nn≥N. Checking terms one at a time can never finish, so the statement about all n≥Nn \ge Nn≥N needs an argument. Two are used.

A monotone tail. If the terms are proven to rise (or fall) to LLL from some index on, then ∣an−L∣|a_n - L|∣an​−L∣ never grows from there, and the first index where it is below ε\varepsilonε is the answer. It is found by doubling and bisection, and it is the least NNN: the term before it is checked to fail.

A dominating sequence. Otherwise, as for sin⁡(n)/n\sin(n)/nsin(n)/n, the asymptotic form of the sequences page gives a bound ∣an−L∣≤C np(log⁡n)mekn|a_n - L| \le C\,n^{p}(\log n)^m e^{kn}∣an​−L∣≤Cnp(logn)mekn that decreases to 0. Past the index where the bound is below ε\varepsilonε every term is within ε\varepsilonε; the finitely many terms before that are examined one by one, walking back to the last one that fails. If the walk reaches it, the NNN is again least.

Sequences with periodic factors, such as (−1)n/n2(-1)^n/n^2(−1)n/n2, are split into the subsequences n=pm+rn = pm + rn=pm+r first, and the answer is one past the last failing index over all of them.

What the certificate is for

A certificate is a plain record of the claim: the formula, the point or limit, ε\varepsilonε, the number found and the argument used. verifyCertificate does not repeat the search. For an NNN it recomputes the limit, checks that the certificate's parts are the subsequences of this very sequence (one for each residue class when there is a factor such as (−1)n(-1)^n(−1)n), proves the monotone direction again or compares the dominating bound with the terms at sampled indices and with ε\varepsilonε, finds the index where each tail argument takes over, and tests the inequality at every index from NNN up to there, one by one. Only then does it test the failure at N−1N - 1N−1 when NNN is claimed least, and the inequality at a spread of later indices. So moving NNN before a bump in the terms is caught: for 1/(1+(n−50)2)1/(1 + (n - 50)^2)1/(1+(n−50)2) and ε=12\varepsilon = \tfrac12ε=21​ the least NNN is 52, and a certificate edited to say N=1N = 1N=1 fails at n=49n = 49n=49. A monotone tail is proven; a dominating bound comes from the asymptotic form and the verifier only samples it against the terms, so for that method the replay is a strong check rather than a second proof. For a δ\deltaδ it cuts the interval into cells and checks ∣f(x)−f(x0)∣<ε|f(x) - f(x_0)| < \varepsilon∣f(x)−f(x0​)∣<ε on each by plain interval evaluation, with no derivative and no root-finding. It returns the list of checks and whether all passed, so a wrong answer from either side shows up as a disagreement.
