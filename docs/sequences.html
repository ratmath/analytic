Sequences

A sequence is a formula in a whole number n, or a rule that makes each term from the one before. sequence and recursive give terms exactly, limits with a proof, and statements such as "decreasing from n = 3 on" that hold for every later term and not only the ones looked at.

const a = sequence("(1 + 1/n)^n");
a.terms(3);            // [2, 9/4, 64/27]   exact
a.limit();             // an interval of width 10^-20 around e
a.bounds();            // { lower, upper, bounded: true }: every term lies between them

const b = sequence("n/(n^2 + 10)");
b.monotone();          // { direction: "decreasing", from: 3, proven: "for every n ≥ 3" }
sequence("n^2/(n + 1)").limit();   // Infinity
sequence("2^n/n!").limit();        // 0, by the ratio of successive terms

Factorials are written n! or (2n)!. The index is n unless you pass { variable }, and starts at 1 unless you pass { from }.

What a limit means here

A sequence ana_nan​ has limit LLL when for every ε>0\varepsilon > 0ε>0 there is an NNN with ∣an−L∣<ε|a_n - L| < \varepsilon∣an​−L∣<ε for all n≥Nn \ge Nn≥N. Computing many terms can suggest a limit and cannot prove one: the definition is about all the terms that were not computed.

The library proves limits from the formula. On a ray x≥Xx \ge Xx≥X it writes the term as

with exact exponents and an interval for ℓ\ellℓ. The limit, or the fact that the sequence grows without bound, is read off the exponents, and the bound on ρ\rhoρ holds for every x≥Xx \ge Xx≥X at once. This is the same machinery as limits at infinity. Where it finds no such form, as for sin⁡n\sin nsinn, limit refuses.

Monotone and bounded

A sequence that is monotone and bounded converges; that theorem is how many limits are shown to exist before they are found. monotone() proves the direction by showing that the derivative of the formula has one sign on a ray [N,∞)[N, \infty)[N,∞), then compares the terms before NNN one by one and moves NNN back as far as they agree. bounds() combines a bound valid on a ray with the finitely many terms before it.

If no proof is found the call refuses. For example the derivative of (1+1/n)n(1 + 1/n)^n(1+1/n)n is a difference of two terms that nearly cancel, and its sign is not settled by this method, although its limit and bounds are.

Two further routes cover cases where the derivative does not settle it. If the derivative HHH tends to 0 and its derivative has one sign on a ray, then HHH has the opposite sign there (a function that decreases to 0 is positive); this is applied up to four levels deep. And for a positive term such as (1+1/n)n(1 + 1/n)^n(1+1/n)n the logarithm is differentiated instead, which turns the power into a product. monotone() reports the route in reason.

Powers with a moving exponent, and the ratio test

A term f(n)g(n)f(n)^{g(n)}f(n)g(n) is rewritten as exp⁡(glog⁡f)\exp(g\log f)exp(glogf), and log⁡f\log flogf for a ratio of polynomials tending to 1 is handled through the exact difference f−1f - 1f−1, so that nothing cancels in floating point. That proves (1+1/n)n→e(1 + 1/n)^n \to e(1+1/n)n→e and limits such as nn/(n! 3n)→0n^n/(n!\,3^n) \to 0nn/(n!3n)→0, where the ratio of successive terms tends to e/3<1e/3 < 1e/3<1.

Oscillation: lim sup and lim inf

A factor such as (−1)n(-1)^n(−1)n, cos⁡(πn)\cos(\pi n)cos(πn) or sin⁡(πn/2)\sin(\pi n/2)sin(πn/2) repeats with a whole period ppp. Along n=pm+rn = pm + rn=pm+r it is a known constant, so each of the ppp subsequences is an ordinary formula in mmm with a limit. Those limits are the only accumulation points; the largest is lim sup⁡an\limsup a_nlimsupan​ and the smallest lim inf⁡an\liminf a_nliminfan​, and the sequence converges exactly when they agree.

const c = sequence("(-1)^n*(1 + 1/n)");
c.accumulation();   // { period: 2, subsequences: [{ along: "n = 2m", limit: 1 }, { along: "n = 2m + 1", limit: -1 }], … }
c.limsup();         // 1
c.liminf();         // -1
c.limit();          // refuses: "no limit: the terms oscillate, with lim sup 1 and lim inf -1 …"
c.supremum();       // { value: 3/2, attained: true, at: 2, reason }
sequence("n/(n + 1)").supremum();   // { value: 1, attained: false, … }: approached, never reached

supremum() and infimum() use the proven direction of each subsequence: a tail that rises has its limit as supremum, not attained; a tail that falls has its first term. The finitely many terms before the tail are compared one by one. For sin⁡n\sin nsinn, which does not repeat on the whole numbers, all of these refuse and say so.

For the NNN that goes with an ε\varepsilonε, see ε, N and δ.

Recursive sequences

const heron = recursive("x/2 + 1/x", { start: 2 });   // x₀ = 2, x_{k+1} = x_k/2 + 1/x_k
heron.terms(5);              // [2, 3/2, 17/12, 577/408, 665857/470832]
heron.fixedPoints([1, 2]);   // [{ point: [1.41421…], multiplier: [≈ 0], kind: "attracting", unique: true }]
heron.limit([1, 2]);         // { limit: [1.41421…], enters: 1, rate: 0.696…, basin: [0.914…, 1.914…] }

If xk+1=g(xk)x_{k+1} = g(x_k)xk+1​=g(xk​) converges and ggg is continuous, the limit is a fixed point, g(x∗)=x∗g(x^*) = x^*g(x∗)=x∗. The multiplier g′(x∗)g'(x^*)g′(x∗) says what happens nearby: errors are multiplied by about g′(x∗)g'(x^*)g′(x∗) each step, so the fixed point attracts when ∣g′(x∗)∣<1|g'(x^*)| < 1∣g′(x∗)∣<1 and repels when ∣g′(x∗)∣>1|g'(x^*)| > 1∣g′(x∗)∣>1.

limit turns that into a proof by the contraction principle. It finds an interval III around a fixed point such that g(I)⊂Ig(I) \subset Ig(I)⊂I and ∣g′∣≤q<1|g'| \le q < 1∣g′∣≤q<1 on III; then ggg has exactly one fixed point in III and every sequence that enters III converges to it, with ∣xk+1−x∗∣≤q ∣xk−x∗∣|x_{k+1} - x^*| \le q\,|x_k - x^*|∣xk+1​−x∗∣≤q∣xk​−x∗∣. It then follows the sequence with interval arithmetic until a term is proven to lie in III. The answer reports the step at which that happened and the rate qqq.

Terms are exact fractions while they stay short (Heron's iteration doubles the number of digits each step) and certified intervals after that.
