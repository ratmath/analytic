Numerical methods

Root-finding methods

Bisection, fixed-point iteration, Newton's method and the secant method, each run in doubles the way a textbook runs it, with its table of iterations. Because the root is also known with certainty (from zeros), every row carries the true error, and the order of convergence is measured, not assumed.

const n = newton("x^2 - 2", 1);
n.iterations;   // [{ n, x, fx, dfx, error }, …]   error = |x − √2|, the real one
n.order;        // 1.9998   observed
n.root;         // the certified root the errors are measured against

bisection("x^2 - 2", [1, 2], { steps: 10 }).iterations;   // each with bound (b − a)/2ⁿ⁺¹ and the true error
secant("x^3 - x - 1", 1, 2).order;                         // about 1.6
fixedPoint("cos(x)", 1).multiplier;                        // g′ at the fixed point: −0.6736…

Order of convergence

With en=∣xn−x∗∣e_n = |x_n - x^*|en​=∣xn​−x∗∣, a method has order ppp when en+1≈Cen pe_{n+1} \approx C e_n^{\,p}en+1​≈Cenp​. Order 1 (with C<1C < 1C<1) gains a fixed number of digits each step; order 2 doubles the number of correct digits each step. From three successive errors,

p≈log⁡(en+1/en)log⁡(en/en−1), p \approx \frac{\log(e_{n+1}/e_n)}{\log(e_n/e_{n-1})}, p≈log(en​/en−1​)log(en+1​/en​)​,

which is what order reports, using the last errors that are still well above rounding.

Newton's method with fractions

With { exact: true }, newton works the way it would by hand with fractions: every iterate is an exact Core Rational, so there is no rounding floor at all. For x2−2x^2 - 2x2−2 from 1 the iterates are 32,1712,577408,665857470832\tfrac32, \tfrac{17}{12}, \tfrac{577}{408}, \tfrac{665857}{470832}23​,1217​,408577​,470832665857​, the convergents of 2\sqrt22​ that the Babylonians used. The price shows in denominatorDigits: the denominators double in length each step, just as the correct digits do. floats holds the double-precision iterates from the same start, so the two can be compared row by row. This needs fff built from +++, −-−, ×\times×, ÷\div÷ and integer powers, so that f(x)f(x)f(x) and f′(x)f'(x)f′(x) are fractions; the default is 6 steps.

Fixed points and the multiplier

For x←g(x)x \leftarrow g(x)x←g(x), xn+1−x∗=g(xn)−g(x∗)≈g′(x∗)(xn−x∗)x_{n+1} - x^* = g(x_n) - g(x^*) \approx g'(x^*)(x_n - x^*)xn+1​−x∗=g(xn​)−g(x∗)≈g′(x∗)(xn​−x∗). So each step multiplies the error by about g′(x∗)g'(x^*)g′(x∗). fixedPoint returns an enclosure of that multiplier at the certified fixed point and the observed ratio of successive errors, which should agree with it. The proof of convergence by the contraction principle is in recursive sequences.

What the true error shows

The root the errors are measured against is the one the method actually converges to. A sign-changing bracket can hold several roots: bisection on (x−1)(x−6)(x−9)(x - 1)(x - 6)(x - 9)(x−1)(x−6)(x−9) over [0,10][0, 10][0,10] keeps [0,5][0, 5][0,5] after the first step and closes in on 1, not on the root 6 nearest the first midpoint, so bisection takes the certified root inside its last bracket. When that root is known only to a small interval, error is an upper bound for the distance, not the exact distance.

A program cannot know its error, so in practice the step size ∣xn+1−xn∣|x_{n+1} - x_n|∣xn+1​−xn​∣ or the residual ∣f(xn)∣|f(x_n)|∣f(xn​)∣ stands in for it. Here the error itself is in the table, measured against a root enclosed to 25 digits, so the stand-ins can be judged. The last rows show the floor that rounding sets: the error stops near 10−1610^{-16}10−16 times the size of the root however many more steps are taken.
